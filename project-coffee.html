The problem

Ordering interfaces look simple until options begin changing price, quantity, cart state, and the next screen. The challenge was keeping those states understandable while the person builds an order.

The solution

I structured the experience around a clear sequence: choose a drink, customize it, add it to the cart, review the order, and continue. Price and cart state update from the choices instead of being hard-coded as separate screens.

Engineering decisions

State-driven UIProduct, option, quantity, and cart state determine what the interface shows.
Clear customizationOptions are grouped so the person can understand what changes the order and what changes the price.
Consistent cart logicThe cart is the single summary of selected products rather than duplicating order state across screens.

System flow

The project is easiest to understand as a flow of responsibilities rather than a single screen.

Menu→Customize→Cart state→Order review

What I’d improve next

Persist carts between sessions.
Add real product availability and inventory integration.
Add order history and authentication.
Add payment integration only after the ordering flow is stable.

What I learned

This project reinforced that interface state should come from a clear data model. Once product options and cart state are represented cleanly, visual updates and price calculations become much easier to keep consistent.
