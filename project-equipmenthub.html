Repository evidence

Inventory model

Equipment can be serialized or quantity-based and tracks status, condition, location, custody, stock thresholds, notes, and photos.

Dashboard logic

The dashboard computes missing items, low stock, maintenance tasks, event readiness, and recent movement activity.

Portable data

The repository documents JSON backup/import so project data can move between browsers.

Deployment

The project is structured for GitHub Pages and is publicly accessible as a static site.

The problem

Equipment teams need more than a list of assets. They need to know where an item is, who has it, whether it is available, whether it needs maintenance, and whether an event is actually ready.

The solution

EquipmentHub organizes equipment, people, locations, movements, events, maintenance, weekly checks, reports, and notifications around one project workspace. The prototype stores data per browser using IndexedDB and includes JSON backup/import for portability.

Engineering decisions

Local-first persistenceIndexedDB keeps projects and operational data available without requiring a backend for the prototype.
Operational statesEquipment records include status, condition, location, responsible person, quantity, minimum stock, and optional photos.
Attention-first dashboardThe dashboard surfaces missing items, low stock, maintenance work, event readiness, and recent activity rather than decorative metrics.
Movement historyMove/assign actions update custody and location while writing movement records for later review.

System flow

The project is easier to understand as a sequence of responsibilities:

Project workspace→IndexedDB stores→Operational modules→Dashboard & reports

What I’d improve next

Add explicit data schema migrations for future IndexedDB versions.
Add stronger role and permission concepts if the prototype moves to a shared backend.
Add automated browser tests around inventory moves and event readiness.
Create exportable audit reports for equipment history.

What I learned

Building EquipmentHub reinforced that operational software is primarily about relationships and state transitions. The interface only becomes useful when the underlying custody, location, maintenance, and event logic is coherent.
